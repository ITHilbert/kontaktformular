## Sicherheit
- **Wer kann die Route aufrufen:** jeder ohne Anmeldung (Absicht, das Formular ist öffentlich). Sie nimmt keine Eingaben an (keine Validierung, kein Mass-Assignment nötig), nur GET/HEAD (POST → 405), `throttle:60,1` wirksam (`X-RateLimit-Limit: 60`).
- **Was sie preisgibt:** nur das CSRF-Token der eigenen Sitzung des Aufrufers — dasselbe, das schon im `<meta name="csrf-token">` jeder Seite und (verschlüsselt) im `XSRF-TOKEN`-Cookie steht. Ohne Cookie bekommt der Aufrufer ein Token einer neuen, eigenen Sitzung, das nur zusammen mit deren Cookie gilt (AK1/AK5 nachgewiesen). Keine Nutzerdaten, keine Sitzungsdaten.
- **Fremde Seiten:** können die Antwort nicht lesen (Randfall 2, im Browser nachgewiesen); `no-store, private` verhindert Ablage in geteilten Caches. Als `<script src>` eingebunden ist `{"token":…}` kein gültiges Skript (Label mit String-Literal → SyntaxError), also kein JSON-Hijacking. CORS hängt am Host: Im Platz greift `config/cors.php` nur für `api/*`, `sanctum/csrf-cookie`, `supports_credentials=false`. Ein Host, der CORS für `*` mit Credentials freigibt, würde das Token lesbar machen — dann wäre aber jede Seite mit Meta-Tag ebenso lesbar; kein neues Risiko des Pakets.
- **CSRF-Prüfung:** unverändert scharf (AK5), keine Ausnahme im Paket.
- **Ausgabe-Escaping:** `show.blade.php` nutzt `{{ }}`.
- **Nebenwirkung (außerhalb der Spec, Task #366):** Die Route liegt hinter `HerkunftErfassen`. Beginnt die Sitzung mit dem Token-Abruf (abgelaufene Sitzung), wird `einstieg: "/kontaktformular/csrf-token"` als First Touch gespeichert (nachgewiesen in `storage/framework/sessions`). Datenqualität, keine Sicherheitslücke; vor #120 ging die Anfrage in diesem Fall ganz verloren.
